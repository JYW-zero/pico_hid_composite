## 四、下次优化方向建议

### 4.1 推荐优先方向（按价值排序）

#### 方向1：性能监控阈值持久化（高优先级第3项）⭐⭐⭐⭐⭐

**价值**：用户设置的性能监控阈值重启后丢失，影响用户体验和调试效率。

**实施方案**：
1. 在配置结构保留字段中添加 `uint16_t perf_thresholds[8]`（16字节，覆盖8个核心任务）
2. 递增配置版本号至 v8，添加版本迁移函数
3. 在 `init_core_services()` 中从配置加载阈值
4. 修改 `CMD_SET_PERF_THRESHOLD` 命令，设置后标记配置脏，延迟保存
5. 添加上位机支持：启动时从设备读取阈值，修改后保存

**预计工作量**：2-3天
**风险**：配置结构变更，需确保向后兼容性

#### 方向2：错误日志Flash磨损均衡（中优先级第4项）⭐⭐⭐⭐

**价值**：当前错误日志使用单个扇区，频繁写入会缩短Flash寿命。多扇区交替写入可延长寿命10倍以上。

**实施方案**：
1. 分配2个扇区用于错误日志存储
2. 实现循环写入机制，每个扇区写满后切换
3. 添加磨损计数，优先使用磨损较少的扇区
4. 或集成LittleFS文件系统（更通用，但复杂度更高）

**预计工作量**：3-4天
**风险**：Flash存储管理变更，需充分测试

#### 方向3：统一代码注释语言（中优先级第5项）⭐⭐⭐

**价值**：当前代码注释中英文混杂，影响可读性和可维护性。统一为英文符合行业标准。

**实施方案**：
1. 制定代码规范文档（注释格式、命名约定、文件头模板）
2. 分模块逐步统一注释语言（优先核心模块：config_hid、usb_descriptors、ipc、watchdog）
3. 使用clang-tidy检查命名规范
4. 更新CI/CD添加注释和命名检查

**预计工作量**：5-7天（分模块进行）
**风险**：低，纯文档和注释修改

#### 方向4：固件签名验证（中优先级第6项）⭐⭐⭐⭐

**价值**：防止恶意固件刷入，提升设备安全性，是商业产品的必备功能。

**实施方案**：
1. 使用ECDSA P-256签名算法（行业标准，轻量级）
2. 在Bootloader中添加签名验证逻辑
3. 上位机添加签名工具（使用OpenSSL或BouncyCastle）
4. 固件映像格式：[签名(64字节) + 版本(4字节) + 长度(4字节) + 固件数据]

**预计工作量**：1-2周
**风险**：Bootloader修改，需充分测试，避免变砖

### 4.2 测试补充方向

#### 方向5：上位机单元测试补充 ⭐⭐⭐⭐

**价值**：当前固件单元测试完善（206个），但上位机单元测试覆盖不足。

**建议补充**：
1. HidTransactionService测试（请求-响应匹配、超时重试、错误处理）
2. DeviceService测试（设备连接/断开、版本协商、配置读写）
3. DfuUpdater测试（固件升级流程、CRC校验、失败回滚）
4. ViewModel测试（命令绑定、状态管理、错误提示）

#### 方向6：集成测试/硬件在环测试 ⭐⭐⭐

**价值**：单元测试无法覆盖的模块（config_hid.c、usb_descriptors.c）需要集成测试。

**建议方案**：
1. 使用树莓派或专用测试板作为USB Host
2. 自动化测试HID命令交互流程
3. 测试配置读写、DFU升级、错误恢复等完整流程
