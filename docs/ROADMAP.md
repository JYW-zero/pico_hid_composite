# HID复合设备 - 开发计划（Python转C版本）

**项目名称：** HID复合设备固件（dev_hid_composite）  
**硬件平台：** Raspberry Pi Pico 2 (RP2350)  
**开发语言：** C11  
**原始版本：** MicroPython原型版  
**目标版本：** C语言版本  
**创建日期：** 2026-08-07  

---

## 一、项目背景与目标

### 1.1 背景
项目最初使用 MicroPython 快速验证了原型功能，包括键盘、鼠标、摇杆、编码器等基本功能。  
但 MicroPython 版本存在以下问题：
- 性能不足，扫描频率低
- 延迟高，实时性差
- 功耗高，不适合电池供电
- 可靠性差，容易崩溃
- 缺少完善的保护机制，不适合量产

因此需要将 MicroPython 原型版重写为 C 语言版本，满足量产要求。

### 1.2 总体目标
将 MicroPython 原型功能完整迁移到 C 语言，并提升至量产标准：
- ✅ 功能完整：保留所有原型功能
- ✅ 性能提升：扫描频率提升10倍以上
- ✅ 低延迟：USB回报率1000Hz，端到端延迟<1ms
- ✅ 高可靠：7×24小时稳定运行，不死机
- ✅ 可维护：模块化、分层设计、易于调试
- ✅ 可测试：单元测试、集成测试、静态分析
- ✅ 低功耗：支持Sleep/Dormant双模式
- ✅ 量产友好：工厂测试模式、错误日志、配置管理

## 二、架构设计

### 2.1 五层架构设计

采用清晰的分层架构，从上到下依赖，从下到上隔离：

```
┌─────────────────────────────────────────┐
│              App层（应用层）              │
│  业务逻辑、状态机、HID报文组装            │
├─────────────────────────────────────────┤
│           Middleware层（中间件）          │
│  通用组件：消抖、调度、看门狗、电源管理    │
├─────────────────────────────────────────┤
│            Device层（设备驱动层）         │
│  外设驱动：键盘、鼠标、摇杆、编码器        │
│  零状态、可重入、多实例、无全局变量        │
├─────────────────────────────────────────┤
│             Board层（板级支持层）         │
│  BSP、引脚映射、配置存储、硬件初始化       │
├─────────────────────────────────────────┤
│            Hardware层（硬件层）           │
│  pico-sdk 官方库（只读，不修改）          │
└─────────────────────────────────────────┘
```

**分层原则：**
- 上层可以调用下层，下层不能调用上层
- 同层模块之间尽量减少依赖
- 每层都有清晰的接口定义
- 每层都可以独立测试

### 2.2 双核架构设计

RP2350是双核Cortex-M33，采用生产者-消费者模式分工：

| 核心 | 角色 | 职责 |
|------|------|------|
| **Core1** | 生产者 | 硬件扫描（键盘、鼠标、编码器、摇杆） |
| **Core0** | 消费者 | USB业务、配置管理、系统监控 |

**Core1（硬件扫描核心）：**
- PAW3395传感器读取（2ms周期）
- 编码器扫描（1ms周期）
- 键盘扫描 + 消抖（5ms周期）
- 摇杆读取（10ms周期）
- 喂DEVICE层看门狗
- 心跳计数器递增

**Core0（业务处理核心）：**
- USB HID上报（1000Hz回报率）
- 按键映射、Fn层处理
- 配置管理、Flash写入
- 系统监控、看门狗巡检
- Core1健康诊断、自动恢复

**核间通信机制：**
- 共享内存 + 自旋锁：安全传递硬件扫描数据
- FIFO命令通道：规范的命令/响应机制
  - SET_DPI：设置DPI
  - SET_ENCODER_REV：设置编码器方向
  - SET_JOYSTICK_DZ：设置摇杆死区
  - PAUSE / RESUME：暂停/恢复扫描（Flash写入用）
  - SLEEP：进入低功耗休眠
  - PING：心跳测试

## 三、功能模块清单

### 3.1 Board层（板级支持）

#### 3.1.1 board.c - 板级初始化
- **功能：** GPIO初始化、时钟配置、SPI初始化、ADC初始化
- **要求：**
  - 所有引脚统一管理，避免冲突
  - 时钟配置准确
  - SPI/ADC等外设初始化完整
  - 双核启动流程规范

#### 3.1.2 config.c - 配置管理
- **功能：** 配置存储与管理
- **设计要求：**
  - ✅ **双备份机制**：A区+B区，各4KB扇区，交替写入
  - ✅ **序列号机制**：seq字段，判断哪个是最新配置
  - ✅ **CRC32校验**：完整性验证，防止配置损坏
  - ✅ **魔数验证**：0x5A5A5A5A，识别有效配置
  - ✅ **版本迁移**：配置版本号，支持旧版本自动迁移到新版本
  - ✅ **写入验证**：写完后读回校验，确保写入正确
  - ✅ **错误记录**：写入失败时记录到fault模块
  - ✅ **弱函数钩子**：config_enter_flash_write/config_exit_flash_write
  - ✅ **关中断保护**：Flash写入时禁用中断，防止意外中断
  - ✅ **双核同步**：写入前暂停Core1，写完后恢复
- **配置项：**
  - DPI设置（400/800/1600/3200）
  - 摇杆死区（ADC原始值）
  - 编码器方向（正常/反转）
  - 64键普通层映射表
  - 64键Fn层映射表
  - 宏配置（8个宏，每个32个动作）
  - 配置序列号
  - CRC32校验

### 3.3 Middleware层（中间件）

- **功能：** 64键批量消抖

#### 3.3.2 fault.c - 统一故障处理
- **功能：** 错误日志记录与管理
- **设计要求：**
  - ✅ **四级故障级别**：INFO / WARN / ERROR / FATAL
  - ✅ **Flash持久化存储**：掉电不丢失
  - ✅ **最多保留16条错误日志**（4KB扇区）

## 四、系统可靠性设计

### 4.1 分层逻辑看门狗
- 三层架构：BOARD / DEVICE / APP
- 每层独立喂狗，任意层卡死都能检测到
- 逻辑超时500ms，硬件看门狗1000ms（2倍余量）
- 硬件看门狗作为最后防线
- 记录最后故障层，方便诊断

### 4.2 Core1异常自动恢复
- 心跳检测：100ms检测一次
- 连续3次（300ms）无心跳 → 判定Core1卡死
- 自动复位并重启Core1，USB连接不中断
- 重启前清空FIFO和共享数据，避免脏数据
- 临时帮喂DEVICE层看门狗，争取重启时间

### 4.3 频繁重启保护
- 滑动窗口：10秒时间窗口
- 窗口内重启超过5次 → 禁用自动恢复
- 禁用后由硬件看门狗触发整机复位
- 避免设备进入"假活"状态（USB连着但功能全挂）

### 4.4 统一故障处理
- 四级故障级别：INFO / WARN / ERROR / FATAL
- 统一记录、统一输出
- Flash持久化存储，掉电不丢失
- 方便调试和问题定位

### 4.5 SPI超时保护
- 键盘SPI：1000us超时
- PAW3395 SPI：500us超时
- 避免硬件异常时整个系统卡死

### 4.6 配置双备份机制
- A/B两个扇区交替写入
- 序列号判断最新版本
- 一个扇区损坏，另一个还能用
- 防止断电丢配置
- CRC32校验，确保完整性
- 版本迁移，向前兼容

### 4.7 Flash写入保护
- 写入前暂停Core1扫描
- 写入后恢复Core1扫描

## 五、低功耗设计

### 5.1 功耗等级
- **ACTIVE**: 正常运行，全速
- **SLEEP**: Sleep模式，CPU停止，外设运行，~5.9mA
- **DORMANT**: Dormant模式，振荡器停止，~3.3mA

### 5.2 运行模式
- **有线模式**: USB已挂载，跟随USB挂起进入Sleep
- **无线模式**: USB未挂载，无操作超时进入Dormant

### 5.3 唤醒源
- PAW3395 MOT引脚（鼠标移动）
- 编码器A/B相（旋转）
- 摇杆按键
- USB恢复信号

### 5.4 双核低功耗
- Core0发SLEEP命令给Core1
- Core1进入WFE休眠
- Core0进入低功耗模式
- 唤醒后Core0发SEV事件唤醒Core1

## 六、鼠标指针加速

### 6.1 算法
经典阈值 + 线性加速：
- 低速（< 5计数/帧）：1:1 精准，适合精细操作
- 中高速：线性增加加速系数
- 上限：最大3倍加速，避免过快失控

### 6.2 配置
- 开关：可通过配置开启/关闭
- 阈值：开始加速的最低速度
- 加速度：每超过阈值1计数增加的系数
- 最大加速：系数上限

## 十、Flash布局设计

基于4MB Flash（Pico 2官方规格）：

| 地址范围 | 大小 | 用途 |
|----------|------|------|
| 0x10000000 ~ | - | 程序代码 |
| ... | ... | ... |
| 0x103FC000 | 4KB | 按键统计区（倒数第4个扇区） |
| 0x103FD000 | 4KB | 错误日志区（倒数第3个扇区） |
| 0x103FE000 | 4KB | 配置A区（倒数第2个扇区） |
| 0x103FF000 | 4KB | 配置B区（倒数第1个扇区） |

**设计原则：**
- 所有持久化数据放在Flash末尾
- 每个模块占用独立的4KB扇区
- 页对齐写入，避免Flash写入错误
- 留出足够空间，方便后续扩展

## 十二、总结

本计划的核心目标是：**把MicroPython原型版升级为C语言量产版**。

**设计目标：**
1. **可靠性**：分层看门狗、双备份配置、错误日志、自动恢复
2. **性能**：双核分工、1000Hz回报率、低延迟
3. **可维护性**：五层架构、模块化、清晰的接口
4. **可测试性**：单元测试、静态分析、性能监控
5. **低功耗**：Sleep/Dormant双模式、多唤醒源
6. **量产友好**：工厂测试模式、配置管理、错误记录

**关键设计理念：**
- 分层设计，高内聚低耦合
- 零状态驱动，可重入多实例
- 防御式编程，处处考虑异常
- 所有假设都要验证
- 失败时要优雅降级，而不是崩溃
