# 编码规范

> 固件 (C)：遵循 Raspberry Pi Pico SDK 官方风格 + MISRA C 简化版
> 上位机 (C#)：遵循微软官方 .NET 编码约定

---

## 零、代码风格

### 固件 (C 语言)：Raspberry Pi Pico SDK 官方风格

本项目固件代码严格遵循 **Raspberry Pi Pico SDK 官方代码风格**，与 SDK 保持一致。

**核心规则：**
- **缩进**：4 个空格，禁止使用 Tab
- **大括号**：K&R 风格，左大括号不换行（`if (x) {`）
- **命名**：
  - 函数、变量：`snake_case`（如 `gpio_put()`）
  - 宏、常量：`UPPER_SNAKE_CASE`
- **指针**：`*` 靠近变量名（`int *ptr`）
- **关键字后加空格**：`if (x)`、`for (i = 0; i < n; i++)`
- **行宽**：建议不超过 100 列

**自动化工具：**
- 配置文件：`firmware/.clang-format`
- VS Code 保存时自动格式化
- 手动格式化：`clang-format -i file.c`

---

### 上位机 (C#)：微软官方 .NET 编码约定

本项目上位机代码严格遵循 **微软官方 .NET 编码约定** 和 .NET 设计准则。

**核心规则：**
- **缩进**：4 个空格
- **大括号**：Allman 风格，左大括号换行（独占一行）
- **命名**：
  - 类、方法、属性、事件：`PascalCase`
  - 接口：`I` 前缀 + `PascalCase`（如 `IHidDevice`）
  - 方法参数、局部变量：`camelCase`
  - 私有字段：`_camelCase`（下划线前缀）
- **语言关键字优先**：用 `string` 而非 `String`，用 `int` 而非 `Int32`
- **异步模式**：I/O 绑定操作使用 `async/await`

**自动化工具：**
- 配置文件：`.editorconfig`（根目录）
- Visual Studio / Rider 自动应用
- 代码分析器实时提示

## 一、目录分层规范
```
include/    头文件目录
  board/    板级支持包，仅硬件初始化、引脚定义
  device/   外设驱动抽象层，与硬件解耦
  middleware/ 中间件，通用工具、算法、服务
  app/      应用业务层，HID报文、主逻辑
src/        源文件目录，与include一一对应
scripts/    工具脚本
docs/       项目文档
```

## 二、命名规范
1. 统一使用 snake_case 命名法
2. 文件名全小写，单词用下划线分隔
3. 宏定义全大写，单词用下划线分隔
4. 结构体、枚举类型以 _t 结尾
5. 枚举常量以模块名前缀开头

## 三、编码硬规则（MISRA简化版）
1. 所有 `if/while/for/else` 无论单行多行，必须包裹 `{}` 大括号
2. 禁止在条件判断内执行赋值操作（`if(a = b)` 禁用）
3. 全部数值运算添加显式强制类型转换，杜绝隐式整型提升
4. 每个函数仅保留单一return出口，统一在函数末尾返回
5. 全程禁用 `malloc/free` 动态内存，全部使用静态分配
6. 模块内部函数、临时变量必须加 `static` 私有化
7. 所有对外函数入口校验入参合法性，异常统一调用 `fault_record()`
8. 驱动结构体严格二分：cfg仅存只读硬件参数，运行状态由上层维护
9. 主循环禁止裸 `while+sleep` 阻塞，必须使用scheduler调度器
10. 硬件引脚宏仅存在于 `board/pins.h`，驱动不得直接引用

## 四、注释规范
1. 每个文件头部添加版权、分层归属、功能说明
2. 每个函数注释功能、入参、返回值、异常场景
3. 关键逻辑、复杂算法添加行内注释
4. 不写无意义注释，代码自解释优先

## 五、构建约束
1. CMakeLists.txt 仅允许追加硬件库，禁止修改原有执行顺序
2. 新增模块必须成对创建 .c 和 .h 文件，分层严格匹配
3. 所有代码必须通过 Cppcheck 静态分析无 Error 级告警
