# FactoryTool 产线演示脚本（约 10 分钟）

> 用途：给产线/主管/客户演示最小闭环，**并在现场拿到形态决策需要的三个答案**。
> 本脚本是“照着操作 + 照着说”的话术，不是产品文档。
> 作者：JYW <JYW@outlook.com>

---

## 0. 前置（演示前 5 分钟自己搞定）

- 笔记本 + 投影；进入 `factorytool/` 目录。
- 环境只需 Python 3.8+，**不用 pip 安装任何东西**（GUI 用系统自带 Tkinter）。
- **先热机跑一遍**，避免首次启动 / 生成报告的卡顿被当成故障：
  - GUI：`python run.py`，点一次“▶ 运行过站流程”，看到绿色 PASS 即正常，关掉即可。
  - 或命令行：`python run.py run --mock --scan P20000000001`
- 演示全程用 **Mock 模拟设备**，不需要真实硬件；先说明这一点，避免对方误以为已经接上产线设备。
- 打开 `reports/` 文件夹备用（第 3 节要现场打开 JSON）。

> 一句话开场：**“现在没有硬件，我用模拟器把整条产线流程跑一遍，验证的是流程和判定逻辑；以后接真机，核心和报告格式都不用改。”**

---

## 1. 好板：完整闭环（约 3 分钟）

**操作（GUI）**
1. `python run.py` 打开界面（默认已加载 `configs/model_pico2.json`，顶部显示“型号：PICO2-HID-COMPOSITE 自检项：2”）。
2. “扫码(SN)”框点 **生成示例SN**（或手动输入 `P20000000001`）。
3. “故障注入”保持 `none`。
4. 点 **▶ 运行过站流程**。

**看点（屏幕上实际出现）**
- 步骤表 **6 行全部绿色 PASS**，顺序固定：
  1. `connect`（连接） 2. `scan`（扫码） 3. `identify`（识别型号）
  4. `write_sn`（写序列号） 5. `self_test:keypad`（按键矩阵自检）
  6. `self_test:sensor`（光学传感器自检）
- 左上出现大号绿色 **PASS**；右侧显示 SN、总耗时（Mock 下约 0.15 秒）、报告路径。
- 日志区逐行打印每个步骤结果。

**要说的一句**
> “从扫码到出厂报告，六个环节自动跑完、自动判定、自动存档，这就是最小闭环。真机上每一步就是一次 USB 交互，耗时换成真实往返时间。”

**（备选）命令行版本**，想顺带展示自动化友好时用：
```bash
python run.py run --mock --scan P20000000001     # 结尾打印“判定：PASS”，退出码 0
```

---

## 2. 故障：定位到具体环节（约 3 分钟）

**操作（GUI）**
1. “故障注入”下拉选 **`write_sn`**（模拟写序列号时 Flash 编程失败）。
2. 扫码框仍是 `P20000000001`，再点 **▶ 运行过站流程**。

**看点**
- 步骤表前 3 步（连接/扫码/识别）仍绿色，**第 4 步 `write_sn` 变红**，后面两项自检照常跑完（尽量多收集信息）。
- 大号 **FAIL**；该步信息列显示“写入序列号失败：Flash 编程错误（模拟）”。
- 命令行下退出码为 **1**（PASS=0 / FAIL=1 / 配置错误=2，方便脚本判断）：
```bash
python run.py run --mock --scan P20000000001 --fault write_sn   # 退出码 1
```

**要说的一句**
> “任何一步失败，都能精确定位到环节，报告里带标准错误码——这里是 FLASH_WRITE(6)。不用整机退回返工，工人一眼知道卡在哪。”

**可现场追加的一枪（按需）**：故障下拉换成 `mfg_locked`（设备已出厂锁定，写号被拒，错误码 12）或 `selftest:keypad`（按键自检失败，能看到 64 键里第几键坏）。说明“同一条流水线，换个故障注入就能复现各种异常”。

---

## 3. 报告：结构化 JSON（约 2 分钟）

**操作**
- 打开 `reports/` 里最新的 `P20000000001_<时间戳>.json`（第 1、2 步各生成一份，可对比 PASS / FAIL 两份）。

**看点（指给对方看的字段）**
- 顶层：`serial`、`model`、`overall`（pass/fail）、`passed`（布尔）、`total_elapsed_ms`、`adapter`、`started_at/finished_at`。
- `device`：型号、固件/协议版本、`capabilities` 能力位图、`device_flags`（好板未锁定时制造位 bit24/bit25 置位；锁定后带出厂锁定标志）。
- `steps[]`：每步的 `name / status / code / message / elapsed_ms / details`，FAIL 那份里 `write_sn` 的 `code` 就是 6。
- `logs[]`：完整文字流水。

**要说的一句**
> “报告是标准 JSON，不是给人眼看的截图。以后不管接 MES、还是夹具脚本自动抓取，直接读这个文件就行，工具本身不用改。”

## 5. 决策对照表（演示后内部用，不必给产线看）

| 三个问题的答案 | 形态结论 | 下一步 |
|---|---|---|
| 全人工、无夹具、不接 MES | **极简 GUI 产品化** | 直接进入阶段 4 出厂闭环 |
| 有 HIL / 自动夹具，脚本自动跑 | **CLI/API 薄壳 + `HilDevice` 适配器** | core 已留好缝，只加外壳和适配器，不重写 |
| 要接 MES | 先定 **MES 接口协议**再动手 | 协议定了再排期 |
| 既有人工工位又有自动线（混合） | **同一核心，GUI + CLI 两个外壳** | 两套壳共用 `core.run_test` 与 JSON |

> 演示后把答案同步给 JYW；无论哪条分支，`core/`（编排、判定、JSON）和 `adapters/base.py`（设备接口）都保持不变，变化的只是“加外壳 / 加适配器 / 加对接”。

## 附：演示故障注入速查

`--fault` / GUI 下拉同值：`connect`（连不上）、`identify`（识别超时）、`wrong_model`（型号不符）、`write_sn`（写号 Flash 失败）、`mfg_locked`（已出厂锁定）、`selftest`（全部自检失败）、`selftest:keypad`、`selftest:sensor`。

GUI 启动：`python run.py` ；命令行：`python run.py run --mock --scan <SN> [--fault <故障>]`。
